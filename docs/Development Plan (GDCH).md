## Graph-Diffused Competing Hazards (GDCH): the “many parallel OPO clocks” model

### Core idea

Think of each OPO as having its own latent “clock” that drives its instantaneous donor-arrival hazard. At any time $t$, each OPO $i \in {1,\dots,N}$ has a conditional intensity (hazard) $\lambda_i(t)$. The national donor stream is the superposition of these parallel hazards, so the next event is generated by a **competing risks** mechanism:
- Total (national) hazard:  
    $\Lambda(t) = \sum_{i=1}^N \lambda_i(t).$
    
- If an event occurs at time t$, its location distribution is:  
    $\mathbb{P}(s=i \mid t, \mathcal{H}_t) = \frac{\lambda_i(t)}{\Lambda(t)}.$
    
What makes it learnable from unmarked data (time + OPO only) is that the hazards are not static. Each OPO has a latent state $z_i(t) \in \mathbb{R}^d$ that:

1. evolves continuously between events (a continuous-time dynamical system), and
    
2. jumps at event times (to encode self-excitation, refractory effects, and shared shocks).
    

The “graph-diffused” part adds an inductive bias: latent states and/or shocks can propagate across nearby OPOs via a graph Laplacian built from your distance matrix. This is your domain prior that geographically close regions can share latent drivers even if the data signal is weak.

Neural ODE training and adjoint differentiation are well supported by Torchdiffeq. ([arXiv](https://arxiv.org/abs/1806.07366?utm_source=chatgpt.com "Neural Ordinary Differential Equations"))

## Inputs and preprocessing

### Required inputs

For each event $n=1,\dots,M$:

- timestamp $t_n$ (monotone increasing)
    
- OPO id $s_n \in {0,\dots,N-1}$

You need to use the data-frame (provided in dataframes directory) to provide these.
These are “free signal” from time:

- Calendar features at any continuous time $t$:
    - hour-of-day sin/cos
    - day-of-week sin/cos
    - month-of-year sin/cos
    - a slow trend feature (for multi-year drift), like normalized year fraction
        

- OPO centroids (lat, lon) and your distance matrix $D_{ij}$.
    
### Graph construction
From distances, build a weighted adjacency:
- $W_{ij} = \exp\left(-\frac{D_{ij}^2}{2\sigma^2}\right)$
- Degree $\Delta_{ii}=\sum_j W_{ij}$
- Laplacian $L=\Delta-W$
You will use $L$ inside the continuous dynamics (diffusion term) and optionally to smooth jump propagation.

---
I will describe a concrete, implementable design that works well in Torchdiffeq and is still “novel” in the way it couples (1) graph diffusion, (2) jump ODE dynamics, and (3) competing hazards.
#### 1) Time embedding module

A small MLP that maps continuous time features to a vector:

- Input: $\phi(t) \in \mathbb{R}^{d_t}$ (sin/cos calendar + trend)
    
- Output: $g(t) \in \mathbb{R}^{d_g}$
    

Implementation detail: Make it purely deterministic given $t$ so you can query it inside the ODE function.

#### 2) Node embeddings (optional but useful)

Learned embedding per OPO:

- $e_i \in \mathbb{R}^{d_e}$ (nn.Embedding)
    

These let the model learn different baselines and different responses to the same calendar signal.

#### 3) Continuous-time latent dynamics (Neural ODE with graph diffusion)

Stack all node states into a matrix $Z(t) \in \mathbb{R}^{N \times d}$, where row $i$ is $z_i(t)$.

A good starting dynamics (stable and expressive) is:

$  
\frac{dZ}{dt}  
= -\alpha Z

- \beta L Z
    

- F_\theta\big(g(t), E, Z\big)  
    $
    

Where:

- $\alpha>0$ is a learnable decay (use softplus to constrain)
    
- $\beta>0$ is a learnable diffusion strength (softplus)
    
- $LZ$ is graph diffusion across OPOs
    
- $F_\theta$ is a small neural forcing term. Keep it low capacity to avoid overfitting.
    

Practical parameterization of $F_\theta$ that is OPO-scalable and Torchdiffeq-friendly:

- compute a global forcing vector $u(t)=\text{MLP}_u(g(t)) \in \mathbb{R}^{d}$
    
- compute per-node gates $r_i(t)=\sigma(\text{MLP}_r([g(t), e_i])) \in (0,1)^d$
    
- then forcing row-wise: $F_i(t)=r_i(t) \odot u(t)$
    

So forcing is mostly “shared national driver” modulated per OPO.

Torchdiffeq usage: implement an `nn.Module` ODE function `forward(t, y)` and integrate with `odeint` or `odeint_adjoint`. Torchdiffeq notes that the adjoint interface expects the dynamics as an `nn.Module`. ([GitHub](https://github.com/rtqichen/torchdiffeq/blob/master/examples/README.md?utm_source=chatgpt.com "torchdiffeq/examples/README.md at master"))

#### 4) Event jump module (discrete updates at arrivals)

At each event time $t_n$ at location $s_n$, apply a jump to the latent states.

A flexible, still-stable jump design:

1. Compute an impulse vector from local state and time:  
    $  
    \delta_n = J_\psi\big(z_{s_n}(t_n^-), g(t_n), e_{s_n}\big) \in \mathbb{R}^{d}  
    $
    
2. Apply it to the event node and optionally diffuse part of it to neighbors:
    

- self jump: $z_{s_n}(t_n^+) = z_{s_n}(t_n^-) + \delta_n$
    
- neighbor spillover: for all nodes $i$:  
    $  
    z_i(t_n^+) = z_i(t_n^-) + \eta \cdot \kappa_{i,s_n}, \delta_n  
    $  
    where $\kappa_{i,s} \propto \exp(-D_{is}^2/2\sigma_J^2)$ and $\sum_i \kappa_{i,s}=1$.
    

This “shock propagation” is a novelty lever: it bakes in spatial coupling without requiring marks.

### 5) Intensity head (competing hazards)

Define each OPO intensity as:

$\lambda_i(t) = \text{softplus}\left( b_i + w^\top z_i(t) + h_\omega(g(t), e_i)  \right) + \epsilon$

Where:

- $b_i$ is a learned baseline (initialize to log base rate if you want faster convergence)
    
- $w \in \mathbb{R}^d$ is shared or per-node
    
- $h_\omega$ is a small MLP producing a scalar “calendar boost” per node
    
- $\epsilon \sim 10^{-8}$ prevents log(0)
    

This produces:

- national hazard $\Lambda(t)=\sum_i \lambda_i(t)$
    
- conditional location distribution at time $t$: $p_i(t)=\lambda_i(t)/\Lambda(t)$
    

### 6) Key trick: augment the ODE state with the cumulative hazard integral

The log-likelihood requires integrals of $\Lambda(t)$. Instead of doing quadrature manually, augment the state with a scalar accumulator $A(t)$:

$$  
\frac{dA}{dt} = \Lambda(t)  
$$

Then over any interval, $\int_{t_a}^{t_b}\Lambda(t),dt = A(t_b)-A(t_a)$ directly from the solver output (up to solver tolerance). This is extremely convenient in Torchdiffeq and makes the implementation much cleaner.

Torchdiffeq supports general augmented states and event termination (useful later for sampling). ([GitHub](https://github.com/rtqichen/torchdiffeq?utm_source=chatgpt.com "rtqichen/torchdiffeq: Differentiable ODE solvers with full ..."))

## Training objective and loss functions

### Point process negative log-likelihood (primary loss)

For an observed sequence ${(t_n, s_n)}_{n=1}^M$ over window $[T_0, T_1]$, the standard multivariate point process log-likelihood under conditional intensities $\lambda_i(t)$ is:

$$  
\log p(\text{data}) =  \sum_{n=1}^{M} \log \lambda_{s_n}(t_n) -\int_{T_0}^{T_1}\sum_{i=1}^N \lambda_i(t), dt  
$$

So the training loss is:

$$  
\mathcal{L}_{NLL}= \int_{T_0}^{T_1}\Lambda(t),dt - \sum_{n=1}^{M} \log \lambda_{s_n}(t_n)  
$$

This is exactly what the augmented accumulator $A(t)$ gives you efficiently. This likelihood form and the “sum of intensities over dimensions” structure is widely used in multivariate temporal point process modeling. ([Proceedings of Machine Learning Research](https://proceedings.mlr.press/v213/shou23a/shou23a.pdf?utm_source=chatgpt.com "Influence-Aware Attention for Multivariate Temporal Point ..."))

### Regularizers options:
1. **Stability regularizer on latent magnitude**

	- Penalize large latent norms: $\lambda_z \sum_n |Z(t_n^-)|_F^2$  
	    This reduces blow-ups and makes the ODE solver happier.
    
2. **Diffusion strength prior**
    
	- Keep $\beta$ modest unless data supports large coupling:
    
	    - either L2 on $\beta$
        
	    - or parameterize $\beta = \text{softplus}(\tilde\beta)$ and regularize $\tilde\beta$
        

3. **Jump magnitude regularizer**
    

	- $\lambda_J  = \sum_n |\delta_n|^2$

## Training procedure (sequential, truncated BPTT, Torchdiffeq)

### Full forward pass through one sequence (conceptually)

Let state be $Y(t) = (Z(t), A(t))$.

1. Initialize:
    

- $Z(T_0) = Z_0$ (learned parameter, or zeros)
    
- $A(T_0)=0$
    

2. For each interval $[t_n, t_{n+1}]$:
    

- Apply jump at $t_n$ using $s_n$: $Z(t_n^+) = \text{Jump}(Z(t_n^-), s_n, t_n)$
    
- Integrate augmented ODE from $t_n$ to $t_{n+1}$ to get $Z(t_{n+1}^-), A(t_{n+1}^-)$
    
- Add event log term for event $n+1$ using the pre-jump state:
    
    - $\log \lambda_{s_{n+1}}(t_{n+1})$ evaluated at $Z(t_{n+1}^-)$
        
- Accumulate integral term from accumulator:
    
    - $A(t_{n+1}^-)-A(t_n^+)$
        

Important detail: evaluate $\lambda_{s_{n+1}}(t_{n+1})$ before applying the jump for event $n+1$, since the conditional intensity is defined given history just before the event.

### Making this trainable at 100k+ events

A practical approach is truncated backpropagation through time:

- Process the event stream sequentially in chunks of length $K$ (example: 512 or 2048 events).
    
- At chunk boundaries:
    
    - carry forward the end state as the next chunk’s initial state
        
    - call `.detach()` on the carried state to cap the backprop graph
        

This gives you:

- a stateful model that sees long histories across an epoch
    
- bounded memory use
    

### Choice of ODE solver and tolerances

- Use `dopri5` as a default.
    
- Use relative and absolute tolerances tuned for stability (example: `rtol=1e-4`, `atol=1e-6`).
    
- Strongly consider rescaling time to days (float32 friendly).
    

Torchdiffeq’s `odeint_adjoint` can be used to reduce memory for long integrations, but it changes numerical behavior. Implement both and compare. ([GitHub](https://github.com/rtqichen/torchdiffeq/blob/master/examples/README.md?utm_source=chatgpt.com "torchdiffeq/examples/README.md at master"))

## Inference: what predictions you can generate

Given history up to time $t_0$, you can compute $Z(t_0^-)$ by running the trained model forward. Then you can produce:

### 1) Instantaneous hazard surfaces

At any time $t$:

- per-OPO hazard vector $\lambda(t)\in\mathbb{R}^N$
    
- national hazard $\Lambda(t)=\sum_i \lambda_i(t)$
    
- conditional location probabilities $p_i(t)=\lambda_i(t)/\Lambda(t)$
    

This is useful for interpretable plots and for checking diurnal or seasonal effects per OPO.

### 2) Next-event time distribution

The waiting time $\tau$ has survival:  
$$
S(\tau) = \exp\left(-\int_{t_0}^{t_0+\tau}\Lambda(u),du\right)  
$$  
and density:  
$$ 
f(\tau)=\Lambda(t_0+\tau),S(\tau)  
$$

You can compute quantiles by integrating the augmented hazard forward until $A(t)=q$ where $q$ is the target cumulative hazard.

### 3) Next-event location distribution (two versions)

- Conditional on a candidate event time $t$: $p_i(t)=\lambda_i(t)/\Lambda(t)$.
    
- # Marginal over the random next-event time:  
    $$  
    \mathbb{P}(s=i\ \text{is next})
    
    \int_0^\infty  
    \frac{\lambda_i(t_0+\tau)}{\Lambda(t_0+\tau)}  
    f(\tau), d\tau  
    $$  
    This second one is more expensive but is the “true” next-location marginal.
    

### 4) Fast sampling of the next event using `odeint_event` (very practical)

Because you have $dA/dt=\Lambda(t)$, you can sample the next event time by:

- draw $u \sim \text{Uniform}(0,1)$
    
- set target $q=-\log u$
    
- integrate the augmented ODE forward and stop when $A(t)-q=0$ using Torchdiffeq event handling
    

Torchdiffeq explicitly supports terminating ODE integration via `odeint_event`. ([GitHub](https://github.com/rtqichen/torchdiffeq?utm_source=chatgpt.com "rtqichen/torchdiffeq: Differentiable ODE solvers with full ..."))

Then sample the location at that sampled time:

- compute $p_i(t)=\lambda_i(t)/\Lambda(t)$
    
- sample $s \sim \text{Categorical}(p(t))$
    

This gives you a full generative simulator consistent with your learned model.

### 5) Multi-step forecasts over a horizon

Over horizon $[t_0, t_0+H]$, you can output:

- expected count for each OPO:  
    $\mathbb{E}[N_i] = \int_{t_0}^{t_0+H} \lambda_i(t),dt$
    
- expected national volume:  
    $\int_{t_0}^{t_0+H}\Lambda(t),dt$
    
- simulated event sequences and predictive intervals via repeated sampling

## Adjacent, practical advice before you code

1. **Start with a “linear-only” dynamics baseline**  
    Set $F_\theta \equiv 0$ and use only $-\alpha Z - \beta LZ$ plus jumps. Get that training and likelihood stable first. Then add forcing MLPs.
    
2. **Use the augmented hazard accumulator from day 1**  
    It makes the likelihood implementation and next-event sampling much cleaner than doing quadrature repeatedly.
    
3. **Be explicit about what “space” means**  
    If your “space” is only the 59 OPOs, the best you can hope for is a calibrated categorical distribution across 59 nodes. GDCH helps you learn smooth spatial coupling and time-dependent hazards, but it will not invent signal that is not present in the unmarked history.
